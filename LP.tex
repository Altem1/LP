\phantomsection
\addcontentsline{toc}{subsection}{Entidad}
\subsection*{Descripción de la Estructura Entidad:}

La estructura es el molde inicial de nuestro Diccionario en formato de base de datos de acceso aleatorio. Se establece un alias \texttt{cadena} para asegurar que cada registro tenga el mismo tamaño.

\campo{cadena nombre:}{Identificador único de cada registro de entidad (máximo 30 caracteres).}
\campo{long atr:}{Puntero tipo \texttt{long} que conecta la entidad con su lista de atributos.}
\campo{long data:}{Dirección física en el archivo donde se almacenan los registros de datos reales.}
\campo{long sig:}{Enlace a la siguiente entidad, permitiendo una estructura de lista ligada.}

\bigskip

\begin{lstlisting}[caption=Estructura de Datos de Entidad, label=code:entidad]
#ifndef ENTIDAD_H_INCLUDED
#define ENTIDAD_H_INCLUDED
#include <iostream>
#include <cstdio>

typedef char cadena[30];
struct Entidad
{
    cadena nombre;
    long atr;
    long data;
    long sig;
};
#endif
\end{lstlisting}

\phantomsection
\addcontentsline{toc}{subsection}{Atributos}
\subsection*{Descripción de la Estructura Atributo:}

Esta estructura es el molde para las columnas de nuestro Diccionario. Al igual que en la entidad, se usa el alias \texttt{cadena} para mantener el tamaño fijo en el archivo binario y evitar que los registros se desfasen. En esta estructura observamos las siguientes declaraciones:

\campo{cadena nombre:}{Identificador del atributo dentro de la entidad.}
\campo{unsigned int tipo:}{Código numérico que define el tipo de dato (ej. entero, flotante, cadena).}
\campo{unsigned int tamano:}{Longitud en bytes que ocupará el valor del atributo en el registro.}
\campo{char iskp:}{Bandera (flag) que indica si el atributo funciona como llave primaria (Primary Key).}
\campo{long sig:}{Puntero lógico (offset) que enlaza con el siguiente atributo de la entidad.}
\campo{cadena descripcion:}{Información adicional o etiqueta descriptiva del campo.}
\campo{char null:}{Indicador booleano que define si el campo permite valores nulos.}

\bigskip

\begin{lstlisting}[caption=Estructura de Datos de Atributos, label=code:atributos]
#ifndef ATRIBUTO_H
#define ATRIBUTO_H

typedef char cadena [30];

typedef struct{
    cadena nombre;
    unsigned int tipo;
    unsigned int tamano;
    char iskp;
    long sig;
    cadena descripcion;
    char null;
}Atributo;

#endif
\end{lstlisting}

\subsection*{Descripción del Objeto CDiccionario:}

La clase \texttt{CDiccionario} funciona como el administrador principal del sistema. En su parte privada, contiene las variables necesarias para controlar el flujo del archivo binario y saber exactamente en qué parte del disco estamos parados mientras el usuario navega. En esta sección observamos las siguientes declaraciones:

\campo{FILE *arch:}{Es el puntero al archivo físico donde se almacenan todas las entidades, atributos y datos.}
\campo{Entidad activa:}{Representa la entidad que el usuario está manipulando o consultando en ese momento.}
\campo{long dir:}{Guarda la dirección física (offset) actual dentro del archivo para las operaciones de lectura/escritura.}
\campo{int nAtributos:}{Es un contador que lleva el registro de cuántos atributos tiene la entidad seleccionada.}
\campo{long tambloque:}{Almacena el tamaño del bloque activo para gestionar correctamente el espacio en el archivo.}
\campo{char nombreArchivo[50]:}{Es el arreglo donde se guarda el nombre del archivo que el usuario decide abrir o crear.}

\section[Funciones Entidad]{Funciones \hfill \fontsize{14}{17}\selectfont Archivo}
\phantomsection
\addcontentsline{toc}{subsection}{Menu}
\subsection*{Menu}
\textbf{Prototipo:} \verb|void CDiccionario::menu();|\\
La función \verb|menu()| simplemente muestra en consola las opciones 
principales del sistema, imprimiendo las opciones para crear un archivo nuevo, 
abrir un archivo existente o salir del programa, sirviendo como interfaz 
inicial para el usuario.

\phantomsection
\addcontentsline{toc}{subsection}{Nuevo}
\subsection*{Nuevo}
\textbf{Prototipo:} \verb|void CDiccionario::Nuevo();|\\
Esta función es la encargada de crear un archivo binario desde cero, primero 
pide al usuario el nombre del archivo, después intenta abrirlo con 
\verb|rb| para verificar que no exista previamente y evitar sobreescribirlo, 
en caso de que no exista lo crea con \verb|wb+|, inicializa la cabecera de 
entidades escribiendo un -1 al inicio del archivo, y finalmente redirige al 
usuario llamando a \verb|Menu_Entidades()|.

\phantomsection
\addcontentsline{toc}{subsection}{Abrir}
\subsection*{Abrir}
\textbf{Prototipo:} \verb|void CDiccionario::abrir();|\\
Esta función permite cargar un diccionario de datos previamente creado, 
solicita al usuario el nombre del archivo y hace uso de \verb|fopen| con la 
instrucción \verb|rb+| para lectura y escritura, verifica si el archivo es 
nulo para avisar que no existe, en caso contrario confirma su apertura y 
manda a llamar a la función \verb|Menu_Entidades()| para comenzar a trabajar.

\section[Funciones Entidad]{Funciones \hfill \fontsize{14}{17}\selectfont Entidad}

\phantomsection
\addcontentsline{toc}{subsection}{Menu Entidades}
\subsection*{Menu Entidades}
\textbf{Prototipo:} \verb|void CDiccionario::Menu_Entidades();|\\
La función \verb|menu_Entidades()| muestra un menú interactivo por consola para administrar
las funciones relacionadas a Entidades. Funciona por medio de un ciclo \texttt{do-while}
y un \texttt{switch-case} que lee la opción del usuario, para ejecutar acciones como
dar de alta, consultar, eliminar o modificar entidades, por consiguiente permitir
la navegación hacia la edición de sus atributos y datos.

\phantomsection
\addcontentsline{toc}{subsection}{Captura Entidad}
\subsection*{Captura Entidad}
\textbf{Prototipo:} \verb|Entidad CDiccionario::CapturaEntidad();|\\
La función \verb|CapturaEntidad()| es la plantilla principal para crear registros, se usa
una variable de tipo Entidad, primero se le pide al usuario el nombre de la entidad, después
se inicializa las variables \texttt{nueva.atr} "conexión con la lista de atributos", \texttt{nueva.data} "la dirección"
real de donde se encuentran los datos de los bloques, y \texttt{nueva.sig} que es la dirección a la
siguiente entidad, con esto se crea un registro nuevo con sus listas vacías.

\phantomsection
\addcontentsline{toc}{subsection}{Alta Entidad}
\subsection*{Alta Entidad}
\textbf{Prototipo:} \verb|void CDiccionario::altaEntidad();|\\
Esta función es la encargada de verificar que todo esté en condiciones para que se cree una entidad,
primero manda a llamar \verb|CapturaEntidad| para crear un registro temporal, seguido de esto
viene la verificación con la función \verb|buscaEntidad| para verificar que no haya una entidad con
ese mismo nombre, en caso que no exista usa la función \verb|escribeEntidad(nueva)| y guarda la dirección
en un \verb|long dir| para finalmente usar la función \verb|insertaEntidad| para escribir en el archivo.

\phantomsection
\addcontentsline{toc}{subsection}{Busca Entidad}
\subsection*{Busca Entidad}
\textbf{Prototipo:} \verb|long CDiccionario::buscaEntidad(char nombre[1]);|\\
La función \verb|long CDiccionario::buscaEntidad(char nombre[])| verifica si se encuentra la entidad,
en caso de que sí la encuentre dentro del recorrido \verb|while(cab != -1)| regresa la dirección
en donde se encuentra, en caso contrario regresa un valor de -1, dentro del ciclo hace un string compare
de la posición donde se encuentra y el nombre que se le haya pasado.

\newpage

\phantomsection
\addcontentsline{toc}{subsection}{Get Cabecera Entidades}
\subsection*{Get Cabecera Entidades}
\textbf{Prototipo:} \verb|long CDiccionario::getcabeceraEntidades();|\\
Esta función es la encargada de obtener la dirección dentro del archivo de donde inicia nuestra lista
de entidades, empieza usando un \verb|long dir|, para después con \verb|fseek| dirigirse
al inicio de nuestro archivo, con un \verb|fread| extraemos la dirección y la guardamos en la variable
\verb|long dir|, sabemos que esa es la cabecera ya que todo el programa está construido para que en el inicio
del archivo se encuentra nuestra cabecera de la lista de entidades.

\phantomsection
\addcontentsline{toc}{subsection}{Lee Entidad}
\subsection*{Lee Entidad}
\textbf{Prototipo:} \verb|Entidad CDiccionario::leeEntidad(long dir);|\\
Se encarga de extraer la entidad del archivo, esta función llega con una
dirección, esa dirección a partir del \verb|buscaEntidad|, es usada para
moverse dentro del archivo, hacer una copia y regresar esa copia para su
posterior modificación o consulta.

\phantomsection
\addcontentsline{toc}{subsection}{Escribe Cabecera Entidades}
\subsection*{Escribe Cabecera Entidades}
\textbf{Prototipo:} \verb|void CDiccionario::EscribeCabEntidades(long cab);|\\
La función empieza con un paso de parámetro de la cabecera, dentro de esta
se mueve al inicio del archivo y en ese inicio escribe lo que haya tenido
el parámetro de nombre cab.

\phantomsection
\addcontentsline{toc}{subsection}{Escribe Entidad}
\subsection*{Escribe Entidad}
\textbf{Prototipo:} \verb|long CDiccionario::escribeEntidad(Entidad ant);|\\
Esta función se encarga de registrar físicamente una nueva entidad en el archivo,
donde se le pasa una copia de la entidad, la funcion usa un \verb|fseek| con \verb|SEEK_END|
para ir hasta el final del ultimo registro del archivo y en ese espacio de memoria
usa un \verb|fwrite| para guardarlo en el archivo

\phantomsection
\addcontentsline{toc}{subsection}{Inserta Entidad}
\subsection*{Inserta Entidad}
\textbf{Prototipo:} \verb|void CDiccionario::insertaEntidad(Entidad nvo, long dir);|\\
Esta función se encarga de enlazar secuencialmente de manera
lógica una nueva entidad verificando tres casos: si el archivo
está vacío, si va al inicio apoyándose de un \verb|strcmp|,
o si busca su lugar usando un ciclo \verb|while|. En esencia,
como \verb|escribeEntidad| siempre guarda físicamente los datos
al final, esta función solo reconecta las variables \verb|nvo.sig|
para que apunten de manera correcta y mantengan el orden.

\phantomsection
\addcontentsline{toc}{subsection}{Consulta Entidades}
\subsection*{Consulta Entidades}
\textbf{Prototipo:} \verb|void CDiccionario::ConsultaEntidades();| \\
Esta función es la encargada de imprimir en consola las entidades que
se encuentran dentro de nuestro archivo. Para ello, hace uso de la función
\verb|getcabeceraEntidades| para ver dónde inicia la cabecera de la entidad;
subsecuentemente hace uso de un ciclo \verb|while (cab != -1)|, el cual va
imprimiendo cada entidad con la dirección de sus componentes.

\phantomsection
\addcontentsline{toc}{subsection}{Baja Entidad}
\subsection*{Baja Entidad}
\textbf{Prototipo:} \verb|void CDiccionario::BajaEntidad();|
Su unica funcion es preguntar al usuario por el nombre de la
entidad, este nombre se lo pasa a la función \verb|EliminaEntidad|
en caso de que no exista muestra en consola un aviso al usuario,
por el contrario si existe, muestra un aviso que fue eliminado.

\phantomsection
\addcontentsline{toc}{subsection}{Elimina Entidad}
\subsection*{Elimina Entidad}
\textbf{Prototipo:} \verb|long CDiccionario::EliminaEntidad(char nombre[]);|
Esta funcion empieza haciendo una verificación, si el archivo esta vacio
regresa un -1, para despues verificar si el lugar actual donde esta parado es
la entidad a borrar, en caso que no hace un recorrido donde hace uso de
\verb|while & strcmp|, para encontrar donde esta, uso una varible anterior
para poder hacer la desconexion de la entidad, no borra nada dentro del archivo
solo desceonecta y conecta con su inmediato siguiente, lo actualiza en el archivo
con la función \verb|reescribeEntidad|.

encuentre dentro del recorrido \verb|while(cab != -1)| regresa 
la dirección en donde se encuentra, en caso contrario regresa 
un valor de -1, dentro del ciclo hace un string compare de

\addcontentsline{toc}{subsection}{Inserta Atributo}
\subsection*{Inserta Atributo}
\textbf{Prototipo:} \verb|void CDiccionario::insertaAtributo(Atributo nvo, long dir);|\\
Esta función se encarga de enlazar secuencialmente de manera lógica un nuevo atributo verificando tres casos: si en el caso que la cabecera \verb|activa.atr| sea -1 "Lista vacía", se enlaza directo, el segundo caso ocurre cuando el atributo se encuentra al inicio, o sea que el \verb|strcmp| sea mayor a 0 decidiendo así que va antes, el tercer caso es cuando tiene que hacer una búsqueda apoyándose de un \verb|while| que recorre toda la lista mientras no llegue al final, dentro usa otro \verb|strcmp| para ver en qué lugar se encuentra su inmediato.\\newline
En esencia la función hace reconexión entre la variable 
\verb|nvo.sig| para que quede de manera ordenada, todos los 
\verb|EscribeAtributo| siempre hacen el write al final por 
tanto lo único que cambia esta función son las direcciones a 
las cuales van apuntando de manera ordenada.

\subsection*{Consulta Bloques}
\textbf{Prototipo:} \verb|void CDiccionario::consultaBloques();|\\
Esta función es la encargada de imprimir en consola los 
registros que se encuentran dentro del archivo. Para ello, 
hace uso de \verb|activa.data| para ver dónde inicia la cabecera, 
imprime los nombres de los atributos, y subsecuentemente hace 
uso de un ciclo \verb|while (cab != -1)| el cual va imprimiendo 
cada bloque haciendo las conversiones de tipo correspondientes.

\phantomsection
\addcontentsline{toc}{subsection}{Busca Bloque}
\subsection*{Busca Bloque}
\textbf{Prototipo:} \verb|long CDiccionario::buscaBloque(void *bloquebus);|\\
La función \verb|buscaBloque| verifica si se encuentra el registro, 
en caso de que sí lo encuentre dentro del recorrido 
\verb|while(cab != -1)| comparando con la función 
\verb|comparaBloques| regresa la dirección en donde se encuentra, 
en caso contrario regresa un valor de -1, moviéndose siempre 
leyendo el apuntador siguiente de cada bloque.

\phantomsection
\addcontentsline{toc}{subsection}{Modifica Bloque}
\subsection*{Modifica Bloque}
\textbf{Prototipo:} \verb|void CDiccionario::modificaBloque();|\\
Esta función permite actualizar los datos de un bloque. 
Empieza pidiendo los nuevos datos con \verb|CapturaBloque|, 
luego hace un recorrido para encontrar el bloque actual y 
desconectarlo enlazando el anterior con el siguiente 
usando \verb|reescribeBloque|, y después guarda y 
reubica el nuevo bloque actualizado utilizando 
\verb|escribeBloque| e \verb|InsertaBloque|.

\phantomsection
\addcontentsline{toc}{subsection}{Baja Bloque}
\subsection*{Baja Bloque}
\textbf{Prototipo:} \verb|void CDiccionario::bajaBloque();|\\
Esta función empieza llamando a \verb|CapturaBloque| para saber 
qué clave buscar, para después hacer un recorrido donde hace uso 
de \verb|while| y \verb|comparaBloques| para encontrar dónde 
está, usa una variable anterior para poder hacer la desconexión 
del bloque, no borra nada dentro del archivo solo desconecta y 
conecta con su inmediato siguiente, actualizando el archivo con 
\verb|reescribeBloque|.

\subsection*{Pide Clave Bloque}
\textbf{Prototipo:} \verb|void *CDiccionario::pideClaveBloque();|\\

\textbf{Prototipo:} \verb|void CDiccionario::eliminaBloque(void* bloque);|\\

comparando con \verb|comparaBloques|, cuando encuentra el registro deseado 
hace la desconexión enlazando el bloque anterior con el siguiente y guardando 
los cambios con \verb|reescribeBloque|, actualizando la cabecera si es el 
primer elemento.

\section{Clave Primaria}
\phantomsection
\addcontentsline{toc}{subsection}{¿Qué es una Clave Primaria?}
\subsection*{¿Qué es una Clave Primaria?}
Una clave primaria en base de datos es aquella que se encarga de la 
identificación única de ciertos registros, como puede ser el ID de un juego o 
la clave de la INE; estos valores dentro de la base de datos nunca se deben 
repetir ya que no pueden existir dos entidades o registros iguales, 
permitiendo su fácil localización e identificación. 
A su vez, estas claves primarias son fundamentales para relacionarse 
con otras tablas, convirtiéndose así en llaves foráneas.

\phantomsection
\addcontentsline{toc}{subsection}{Manejo de la Clave Primaria en el Sistema}
\subsection*{Manejo de la Clave Primaria en el Sistema}
Para gestionar esta regla de validación dentro de nuestro archivo binario, 
el sistema se apoya de las siguientes funciones y lógicas:

\campo{Funciones de Captura:}{La función \texttt{CapturaAt} es la encargada de preguntarle al usuario si el nuevo atributo será clave primaria, guardando el indicador en la variable \texttt{iskp}. Por otro lado, \texttt{CapturaBloque} y \texttt{pideClaveBloque} son las funciones responsables de pedirle al usuario el valor numérico o de texto real para esa clave.}

\campo{Función que la compara:}{La función \texttt{comparaBloques} es la encargada de evaluar exclusivamente la clave primaria de dos registros distintos, determinando cuál va antes o después usando \texttt{strcmp} o restas aritméticas según su tipo de dato, siendo esencial para poder insertar y buscar en orden.}

\campo{Validación (existeKP) e Índice 0:}{Toda esta lógica esta en la función \texttt{cargaAtributos}. Mientras lee los atributos de la entidad, utiliza un contador \texttt{kp} para validar que exista exactamente una sola clave primaria (cumpliendo la función lógica de \textit{existeKP}); si encuentra cero o más de una, manda un error. Además, al encontrarla hace un intercambio de variables en memoria para asegurar que la clave primaria siempre se almacene y fije en el \textbf{índice 0} del arreglo \texttt{arrAtributos}, garantizando así que \texttt{comparaBloques} y demás funciones siempre evalúen el identificador correcto.}

\section{Conclusiones}
Este proyecto fue una representación en crudo de cómo funcionan 
las bases de datos primitivas en un lenguaje de bajo nivel. 
Nos ayudó a comprender de mejor manera cómo funciona la memoria 
estática (\textit{Archivos}) y cómo esta se va cargando 
dinámicamente dentro de nuestra memoria RAM. 
Es importante tener conocimiento de esto, ya que dentro del 
desarrollo real, como por ejemplo en varios juegos indie, 
muchas veces guardan las partidas dentro de archivos binarios; 
de igual manera, los motores de bases de datos operan bajo estos 
mismos principios, aunque de una forma un tanto diferente y 
optimizada.

Por otro lado, descubrimos que el manejo del tipo de dato 
\verb|void*| de alguna forma puede usarse para ofuscar 
información dentro de los archivos, siendo de único conocimiento 
del creador del sistema o requiriendo herramientas especializadas 
para poder traducir y estructurar estos datos en crudo.

Durante las varias fases de desarrollo vimos y aprendimos cómo 
es ir montando un sistema desde cero usando únicamente las bases 
de un lenguaje de bajo nivel. Todo este conocimiento puede ser 
aplicado en la creación de software para componentes de bajos 
recursos o en sistemas basados en redes privadas para lograr una 
mayor velocidad. Con unas cuantas adiciones, este modelo base 
se convertiría en un sistema sumamente rápido y en gran parte 
confiable.

Otro de los aprendizajes importantes fue comprender la diferencia 
entre el espacio físico y el lógico en un medio de almacenamiento. 
Implementar la eliminación lógica nos hizo darnos cuenta de que, 
en los sistemas a bajo nivel, borrar un registro no significa 
destruir su información en el disco, sino simplemente desenlazar 
sus punteros para puentearlo. Esto nos dio una perspectiva muy 
clara de por qué las bases de datos reales necesitan rutinas de 
mantenimiento (como el compactado) para recuperar el espacio 
'muerto' que se va acumulando.

Finalmente, concluimos que el uso de la clave primaria 
(\textit{Primary Key}) es una parte vital en la creación de 
bases de datos. Ésta sirve para la comunicación y relación entre 
tablas dentro de una misma base, y es el único parámetro que no 
desaparece en la normalización de los datos. Es una pieza 
fundamental; el hecho de que solo exista una llave por registro 
ayuda a localizarlos rápidamente y a mantener un orden estricto, 
logrando que sean de fácil acceso, de fácil modificación y de 
fácil borrado, tanto en este sistema que acabamos de desarrollar 
como en aquellos motores profesionales que se usan en la vida real.
